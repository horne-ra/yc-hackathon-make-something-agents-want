# Project overview: Commander.js

This is **Commander.js** v13.1.0, the Node.js library for building command-line interfaces. It's a CommonJS package that also ships an ES module wrapper and TypeScript typings. It requires Node 18 or later and is MIT licensed. I read only the directory tree and `package.json`, not the source files, so the notes on what each file does are inferred from names.

## Source code

| Path | Purpose |
|---|---|
| `index.js` | Main entry point (`main` in `package.json`). |
| `esm.mjs` | ESM entry point, selected through the `exports` map for `import`. |
| `lib/command.js` | Core `Command` implementation: parsing, subcommands, hooks, actions. |
| `lib/option.js` | `Option` definitions. |
| `lib/argument.js` | `Argument` definitions. |
| `lib/help.js` | Help text generation and formatting. |
| `lib/error.js` | Error classes. |
| `lib/suggestSimilar.js` | "Did you mean…?" suggestions for mistyped commands and options. |
| `typings/` | `index.d.ts` (CJS types), `esm.d.mts` (ESM types) and `index.test-d.ts` (type tests run with `tsd`). |

The published package (`files` in `package.json`) includes only `index.js`, `lib/*.js`, `esm.mjs`, the two typings files and `package-support.json`.

## Tests (`tests/`)

- **Framework:** Jest, configured in `jest.config.js`, with `ts-jest` for TypeScript.
- **Layout:** one test file per feature, named by area:
  - `command.*.test.js` covers actions, aliases, hooks, help, executable subcommands, `exitOverride` and similar.
  - `options.*.test.js` covers booleans, env vars, defaults, choices, variadic options, `implies`, `conflicts` and similar.
  - `help.*.test.js` covers help formatting, such as term lengths, wrapping, sorting, styling and visibility.
  - `argument.*.test.js` and `args.*.test.js` cover arguments.
- **Fixtures:**
  - `fixtures/` holds `pm-*` scripts that act as fake executable subcommands.
  - `fixtures-extensions/` holds `.cjs`, `.mjs` and `.ts` variants of the same.
- **Other checks:**
  - `esm-imports-test.mjs` checks the ESM exports.
  - `ts-imports.test.ts` checks the TypeScript imports.

## Documentation and examples

- **Top level:** `Readme.md`, `Readme_zh-CN.md`, `CHANGELOG.md`, `CONTRIBUTING.md` and `SECURITY.md`.
- **`docs/`:** in-depth guides on help, options, parsing and hooks, terminology and deprecated features, plus Chinese translations in `docs/zh-CN/`.
- **`examples/`:** about 50 runnable sample CLIs. Some, such as `pizza`, `deploy` and `pm`, have no file extension and are executable scripts. The rest cover options, arguments, help customisation, nested commands, hooks and so on.

## Tooling and configuration

- **Scripts (`package.json`):**
  - `npm test` runs Jest and the TS type check.
  - `npm run check` runs type checking, ESLint and Prettier.
  - `npm run fix` auto-fixes lint and formatting.
  - `npm run test-esm` tests the ESM entry point.
- **Lint and format:** `eslint.config.js` (ESLint 9 flat config with typescript-eslint), `.prettierrc.js`, `.prettierignore` and `.editorconfig`.
- **TypeScript:** `tsconfig.json`, `tsconfig.js.json` (type-checks the JS source) and `tsconfig.ts.json` (checks the TS usage and typings).
- **CI (`.github/`):** `workflows/tests.yml` and `workflows/codeql-analysis.yml`, plus Dependabot config, a PR template and funding info.
- **Runtime dependencies:** none. Everything in `package.json` is a dev dependency.
